# Практическая работа: совместимость ПО

Псевдоним: Чимин
Вариант: A
Версия стенда: 1.0.0
Попытка: 80e151d6-5f8e-4932-8651-d69092c0e9cf
Дата: 2026-10-31

Цель работы: Научиться сопоставлять требования ПО с конфигурацией ПК, проверять драйверы, изолировать конфликты служб методом чистой загрузки, различать причины сбоев DLL, а также безопасно выполнять обновление данных с возможностью отката.

Исходный инцидент: Вымышленное приложение PrintLab не запускается на учебной модели из-за несоответствия конфигурации, проблем с драйвером, конфликта сторонней службы и устаревших предположений программы о версии ОС. Дополнительно требуется настроить JSON-адаптер и проверить миграцию данных.

Границы модели: Все компьютеры, устройства, драйверы, службы и DLL в стенде — учебные модели. Изменения в браузере не меняют реальную ОС. JSON-адаптер является ограниченным декларативным модулем и не является настоящей DLL или драйвером.

1. Конфигурация

Таблица совместимости:

| Параметр | Исходное значение | Требование приложения | Совместимость | План изменения |
| :--- | :--- | :--- | :--- | :--- |
| ОС | Windows 10 | Windows 11 | ✗ | Установить Windows 11 |
| Архитектура | x86 | x64 | ✗ | Сменить архитектуру на x64 |
| ОЗУ | 4 GiB | ≥ 8 GiB | ✗ | Добавить ОЗУ до 8 GiB |
| Графический API | 11 | 12 | ✗ | Обновить видеокарту |

Гипотеза: Если изменить конфигурацию до требуемых значений, проверка должна пройти успешно.

Метод: Системные требования + msinfo32.

Ход эксперимента:

| № опыта | Конфигурация | Результат | Наблюдения |
| :--- | :--- | :--- | :--- |
| 1 | Win10, x86, 4 GiB, API 11 | REQUIREMENTS_NOT_MET | Все 4 параметра не соответствуют |
| 2 | Win11, x64, 8 GiB, API 12 | REQUIREMENTS_MET | Все 4 параметра совпали |

Диагноз и доказательства: В исходном состоянии (Опыт 1) ни один параметр не соответствовал требованиям. После изменения конфигурации (Опыт 2) проверка прошла успешно. Это доказывает, что причиной сбоя были именно параметры конфигурации.
Вывод и ограничения: Конфигурация приведена в соответствие. Ограничение: стенд моделирует только числа. В реальности нужно проверить поддержку процессора, драйверы под Windows 11 и совместимость видеокарты.

2. Драйвер

Гипотеза: Устаревший пакет не подойдет, так как его архитектура (x86) и ОС (Windows 10) не совпадают с требованиями (x64, Windows 11).

Метод: Диспетчер устройств + Hardware ID.

Ход эксперимента:

| № опыта | Выбранный пакет | Результат | Наблюдения |
| :--- | :--- | :--- | :--- |
| 3 | Устаревший (Win10, x86) | DRIVER_MISMATCH | Не совпали ОС и архитектура |
| 4 | PrintLab USB (Win11, x64) | DRIVER_MATCH | Совпали все 5 признаков |
| 5 | MediaScan USB | DRIVER_MISMATCH | Не совпал Hardware ID |
| 6 | DesignControl USB | DRIVER_MISMATCH | Не совпал Hardware ID |
| 7 | Неизвестный пакет | DRIVER_MISMATCH | Нет подписи и источника |

Диагноз и доказательства: Только Опыт 4 совпал по всем признакам (Hardware ID, ОС, архитектура, подпись, источник). Это доказывает, что для успеха нужна совокупность всех признаков.
Вывод и ограничения: Правильный драйвер подобран по строгому соответствию. Ограничение: успешное сопоставление в модели не доказывает, что устройство будет работать без сбоев. Подпись гарантирует целостность, но не отсутствие ошибок в коде.

3. Чистая загрузка

Гипотеза: Сбой вызывает одна из включенных сторонних служб.

Метод: Чистая загрузка + контролируемые повторы.

Ход эксперимента (бисекция):

| № опыта | Включенные службы | Результат | Вывод |
| :--- | :--- | :--- | :--- |
| 8 | Все 6 служб | APP_START_FAILED | Исходный сбой |
| 9 | Ни одной | APP_STARTED | Сбой из-за сторонних служб |
| 10 | PrintWatch, MediaIndex, DeviceBridge | APP_START_FAILED | Виновник в этой тройке |
| 11 | PrintWatch, DeviceBridge | APP_START_FAILED | Виновник в этой паре |
| 12 | Только PrintWatch | APP_START_FAILED | Виновник — PrintWatch |
| 13 | Все, кроме PrintWatch | APP_STARTED | Отрицательный контроль |


Диагноз и доказательства: Причинно-следственная связь доказана повторным воспроизведением сбоя с единственной службой PrintWatch (Опыт 12) и успешным отрицательным контролем без нее (Опыт 13).

Вывод и ограничения: Конфликтующая служба — PrintWatch. Ограничение: проверена только данная модель. Сочетанные конфликты нескольких служб не исследовались.

4. Мастер и shim

Гипотеза: Программа падает из-за устаревшего предположения о версии ОС. Без shim-профиля симптом сохранится.

Метод: Журнал приложения + тест совместимости.

Ход эксперимента:

| № опыта | Профиль / Сценарий | Результат | Наблюдения |
| :--- | :--- | :--- | :--- |
| 14 | Без исправления | LEGACY_FAILED | Исходный сбой |
| 16 | DisplayScale | LEGACY_FAILED | Не влияет на версию ОС |
| 17 | VersionLie | LEGACY_PASS | Симптом устранен |
| 18 | VersionLie + драйвер ядра | SHIM_DRIVER_LIMIT | Граница shim |
| 19 | VersionLie + DLL x86 в x64 | SHIM_BITNESS_LIMIT | Граница shim |

Диагноз и доказательства: Обоснованный профиль VersionLie подменил ответ о версии ОС, и программа запустилась (Опыт 17). Однако shim не помогает при несовместимом драйвере ядра (Опыт 18) и при загрузке DLL x86 в процесс x64 (Опыт 19).

Вывод и ограничения: Shim исправил устаревшее предположение о версии ОС. Ограничение: shim не создает оборудование, не исправляет драйвер ядра и не решает проблему разрядности DLL.

5. DLL и адаптер

Гипотеза: Разные условия загрузки DLL дадут разные сообщения об ошибках.

Метод: Журнал загрузчика + проверка архитектуры/API.

Ход эксперимента (DLL):

| № опыта | Условия | Результат | Причина |
| :--- | :--- | :--- | :--- |
| 20 | Файл отсутствует | DLL_NOT_FOUND | Ошибка поиска |
| 21 | Архитектуры x64/x86 | DLL_BAD_ARCH | Ошибка архитектуры |
| 22 | Нет экспорта | DLL_MISSING_EXPORT | Ошибка функции |
| 23 | Все условия выполнены | DLL_LOADED | Успешная загрузка |

Ход эксперимента (Адаптер):

| № опыта | Конфигурация адаптера | Результат |
| :--- | :--- | :--- |
| 40 | Пустой модуль (`rules: []`) | ADAPTER_CONFIG (отказ) |
| 24 | JSON с 4 правилами | ADAPTER_PASS (6/6 тестов) |

Итоговый JSON адаптера:

{
  "version": 1,
  "rules": [
    { "from": "job", "to": "id", "op": "copy" },
    { "from": "title", "to": "label", "op": "copy" },
    { "from": "memoryMiB", "to": "memoryGiB", "op": "scale", "fromUnit": "MiB", "toUnit": "GiB" },
    { "from": "state", "to": "status", "op": "enum", "map": { "ready": "active", "held": "paused" } }
  ]
}

Фактические результаты тестов: 2048 MiB -> 2 GiB; 512 MiB -> 0.5 GiB. Статусы ready -> active, held -> paused. Тесты на неверные данные (число строкой, неизвестный статус, отрицательный объем) дали ожидаемые контролируемые отказы.

Диагноз и доказательства: Получены 4 разных результата, что доказывает разные причины сбоев. Адаптер успешно прошел все 6 контрактных тестов.

Вывод и ограничения: Разные ошибки требуют разных методов решения. Адаптер согласует данные, но не исправляет машинный код, ABI или драйверы ядра.

6. Обновление

Гипотеза: Если при обновлении повреждается значение, проверка только количества записей не выявит проблему.

Метод: Копия данных + регрессионные проверки.

Ход эксперимента:

| № опыта | Действие | Результат | Наблюдения |
| :--- | :--- | :--- | :--- |
| 27 | Сохранение копии | BACKUP_SAVED | Копия создана |
| 28 | Миграция с дефектом | MIGRATION_EXECUTED | Подпись повреждена |
| 29 | Сравнение данных | DATA_MISMATCH | Количество совпало, контент — нет |
| 30 | Регрессия (дефект) | REGRESSION_FAILED | Поиск по подписи не работает |
| 31 | Откат | ROLLBACK_PASS | Данные восстановлены |
| 32 | Миграция без потерь | MIGRATION_EXECUTED | Успешно |
| 33 | Сравнение данных | DATA_VERIFIED | Всё совпало |
| 34 | Регрессия (успех) | REGRESSION_PASS | Все 3 проверки пройдены |
| 36 | Повторный откат | ROLLBACK_PASS | Восстановление из копии |

Диагноз и доказательства: При дефекте количество записей сохранилось, но данные повредились (Опыт 29, 30). Откат вернул исходное состояние (Опыт 31). При lossless-миграции данные успешно перенеслись (Опыт 32-34), и повторный откат сработал (Опыт 36).

Вывод и ограничения: Проверка количества не гарантирует сохранность данных. Нужна проверка содержимого и регрессия. Ограничение: откат возвращает только учебный формат данных, без версии приложения.

Заключение, ограничения и источники

Незавершённые проверки: Все 6 этапов пройдены. В этапе 3 исследовался только одиночный конфликт. В этапе 6 откат проверялся только для учебного формата данных.

Ограничения: Стенд — браузерная модель. Успех в модели не гарантирует работоспособность реального оборудования.
